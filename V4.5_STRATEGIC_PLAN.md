```markdown
## STATISTICAL ANALYSIS

### Network Meta-Analysis Model

We performed Bayesian network meta-analysis using a random-effects model
to account for anticipated heterogeneity across studies. The model estimates
relative treatment effects for all pairwise comparisons, borrowing strength
from indirect evidence where direct comparisons are unavailable.

For binary outcomes, we modeled the log odds ratio using:

logit(p_ik) = μ_i + δ_ik

where p_ik is the probability of the event in arm k of study i, μ_i is the
baseline log-odds in study i, and δ_ik is the treatment effect for arm k
relative to the reference arm. Treatment effects were assumed to follow a
normal distribution with between-study heterogeneity τ²:

δ_ik ~ Normal(d_tk - d_t1, τ²)

where d_tk is the pooled effect for treatment k vs reference treatment 1.

### Heterogeneity Assessment

Between-study heterogeneity was quantified using:
- I² statistic (proportion of variance due to heterogeneity)
- τ² (between-study variance)
- Prediction intervals (expected range for future studies)

We interpreted I² values as: <25% (low), 25-50% (moderate), 50-75% (substantial),
>75% (considerable) heterogeneity.

### Inconsistency Assessment

We assessed consistency between direct and indirect evidence using:
1. **Global inconsistency:** Unrelated mean effects (UME) model comparison
2. **Local inconsistency:** Node-splitting for each closed loop

Significant inconsistency (P < 0.05) would trigger exploration of treatment
effect modifiers through meta-regression.

### Sensitivity Analyses

We planned the following sensitivity analyses:
1. Excluding studies at high risk of bias
2. Alternative priors for between-study heterogeneity
3. Fixed-effect model (if heterogeneity minimal)
4. Leave-one-out analysis (influential studies)

### Software

Analyses were conducted in R version [VERSION] using the R2jags package
(interface to JAGS [VERSION]). Bayesian models used 3 chains with 50,000
iterations (20,000 burn-in), assessed for convergence using R-hat < 1.1.
```

## 🔒 SAFEGUARDS & VALIDATION

### 1. Number Locking Mechanism

```r
# Extract all numbers before NLP
lock_numbers <- function(text) {
  numbers <- stringr::str_extract_all(text, "\\d+\\.?\\d*")[[1]]
  return(list(
    original_text = text,
    locked_numbers = numbers,
    number_positions = stringr::str_locate_all(text, "\\d+\\.?\\d*")[[1]]
  ))
}

# Validate no numbers changed after NLP
validate_numbers <- function(original_locked, nlp_output) {
  output_numbers <- stringr::str_extract_all(nlp_output, "\\d+\\.?\\d*")[[1]]

  if (!identical(sort(original_locked$locked_numbers), sort(output_numbers))) {
    warning("NLP MODIFIED NUMBERS - REVERTING TO TEMPLATE")
    return(FALSE)
  }
  return(TRUE)
}
```

### 2. Template Similarity Check

```r
# Ensure NLP output is similar to template (no new claims)
check_template_similarity <- function(template, nlp_output) {
  # Remove numbers (already validated separately)
  template_words <- remove_numbers(template) %>% tokenize()
  output_words <- remove_numbers(nlp_output) %>% tokenize()

  # Jaccard similarity
  intersection <- length(intersect(template_words, output_words))
  union <- length(union(template_words, output_words))
  similarity <- intersection / union

  if (similarity < 0.85) {
    warning("NLP OUTPUT TOO DIFFERENT FROM TEMPLATE - REVERTING")
    return(FALSE)
  }
  return(TRUE)
}
```
