                        CRITICAL SECURITY ISSUES (FIX IMMEDIATELY)
================================================================================

1. KUBERNETES SECRETS EXPOSED IN VERSION CONTROL
   File: k8s/base/configmap.yaml (lines 41-52)
   Problem: Passwords marked "CHANGE_ME_IN_PRODUCTION" - in git history!
   Impact: HIGH - Database credentials, JWT secrets, admin passwords exposed
   Action: Use Sealed Secrets, HashiCorp Vault, or external secret manager

2. MISSING KUBERNETES RBAC
   Problem: No ServiceAccounts, Roles, or RoleBindings defined
   Impact: HIGH - All pods run with default service account (overprivileged)
   Action: Create least-privilege roles per service (backend, redis, postgres)

3. MISSING NETWORK POLICIES
   Problem: All pods can communicate with each other (no isolation)
   Impact: HIGH - Lateral movement if one pod is compromised
   Action: Implement NetworkPolicy: allow Backend↔DB, allow Backend→Redis, deny Frontend↔DB

4. CLIENT PORTAL PASSWORDS IN PLAINTEXT
   File: frontend/modules/client_portal.R (line 180)
   Problem: Passwords stored as plain strings in generated R code
   Impact: HIGH - Client portal authentication trivial to bypass
   Action: Hash passwords with bcrypt; implement request-level auth

5. CORS ALLOWS ALL ORIGINS
   File: backend/api/nlq.py (line 30)
   Problem: allow_origins=["*"] - allows cross-origin requests from anywhere
   Impact: HIGH - CSRF attacks, unauthorized API access
   Action: Restrict to specific domains in production

6. CI/CD DEPLOYMENT NOT IMPLEMENTED
   Files: .github/workflows/deploy.yml, ci-cd.yml (lines 247-253, 123-127)
   Problem: Deployment commands are placeholders/TODOs
   Impact: CRITICAL - Can't actually deploy to production
   Action: Implement kubectl or docker-compose deployment with verification
